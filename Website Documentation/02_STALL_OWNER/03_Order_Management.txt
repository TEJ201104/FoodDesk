1. FEATURE OVERVIEW
--------------------------------------------------------------------------------
The Order Management Hub (/orders) is the central operational ledger and audit repository for all walk-in counter tickets created by the active stall.

It allows stall operators and cashiers to inspect, filter, search, manage, and audit orders across their entire lifecycle. Whether looking up a customer's order placed two minutes ago, tracking unpaid tickets, reprinting a lost thermal receipt, processing a customer refund, or cancelling an order, this module provides complete operational control with full audit trail logging.

Key capabilities include:
- Four top summary metric cards: Total Scoped Orders, Paid Revenue, Completed / Served Orders, and Cancelled / Refunded Orders.
- Multi-criteria real-time search: Instant lookup across Order Numbers, Pickup Tokens, Customer Mobile Numbers, Internal IDs, or Item Names.
- Quick date range filters: All Dates, Today, Yesterday, Last 7 Days, and Custom Date Picker (Asia/Kolkata timezone).
- Independent dual status filters: Kitchen Stage Filter (Received, Preparing, Ready, Completed, Cancelled) and Payment Status Filter (Paid, Partially Refunded, Fully Refunded, Pending, Failed).
- Comprehensive Order Table: High-density data table displaying Order #, Token, Placed At, Items Summary, Payment Status, Grand Total, Kitchen Stage, and Action buttons.
- Slide-over Order Details Drawer: Comprehensive slide-out panel showing complete item breakdowns, customer details, payment history, and sensitive action triggers.
- Sensitive Action Protection: Modal confirmation for cancellations and simulated refunds with mandatory reason inputs and financial balance recalculation.


2. HOW TO ACCESS
--------------------------------------------------------------------------------
- Direct URL: http://localhost:5173/orders
- Sidebar Navigation: Click "Order History" (the third item with the ReceiptText icon) in the stall navigation sidebar.


3. SCREEN LAYOUT
--------------------------------------------------------------------------------
The Order Management Hub is structured into five distinct vertical tiers:

1. Page Header & Quick Workstation Links:
   Stall scope badge, headline ("Order Management Hub"), subtitle, "New POS Order" button, "Kitchen KDS" button, and manual refresh button.

2. KPI Metric Cards Bar:
   Four responsive summary cards displaying Total Scoped Orders, Paid Revenue, Completed / Served, and Cancelled / Refunded.

3. Multi-Filter & Search Console:
   A consolidated control card featuring a wide search input, five date preset buttons, a custom calendar picker, independent kitchen stage dropdown, independent payment status dropdown, active filter reset button, and matching records counter.

4. Orders Data Table:
   The primary data grid displaying all filtered order records with latest order highlight, status badges, price breakdowns, and action buttons.

5. Slide-Over Details Drawer (Conditional):
   A 500px slide-out drawer on the right edge displaying deep order metadata, payment timeline, and action buttons when an order is inspected.


4. DETAILED ELEMENT-BY-ELEMENT EXPLANATION
--------------------------------------------------------------------------------
Every visual and interactive component is detailed below:

A. HEADER & WORKSTATION SHORTCUTS:
- Stall Scope Badge:
  - Text: Store icon + Active Stall Name + Stall ID font-mono.
  - Subtitle: "Module 7 Order Management".
- Title: "Order Management Hub" with ReceiptText icon.
- Header Actions:
  - "New POS Order" Button (Primary): Quick jump to /pos.
  - "Kitchen KDS" Button (Secondary): Quick jump to /kds.
  - Refresh Button: RotateCcw icon. Re-queries local storage records.

B. KPI METRICS CARDS:
- Total Scoped Orders:
  - Data: Total count of orders belonging to currentStall.id.
  - Icon: Hash icon in brand orange box.
- Paid Revenue:
  - Data: Total collected revenue formatted in Indian Rupees (e.g., "₹14,250.00").
  - Source: Sum of grandTotal for all orders where paymentStatus is 'paid' or 'successful'.
  - Icon: CheckCircle2 icon in emerald box.
- Completed / Served:
  - Data: Count of orders where orderStatus === 'completed'.
  - Icon: ChefHat icon in sky-blue box.
- Cancelled / Refunded:
  - Data: Count of orders where orderStatus === 'cancelled' OR paymentStatus === 'refunded'.
  - Icon: RotateCcw icon in rose-red box.

C. MULTI-FILTER ENGINE CONTROLS:
- Text Search Input:
  - Placeholder: "Search by order #, mobile #, item name, or token...".
  - Behavior: Instant substring matching across orderNumber, pickupToken, customerMobile, id, and item names.
- Date Range Presets:
  - Five buttons: "All Dates", "Today", "Yesterday", "Last 7 Days", "Custom".
  - Active State: Solid brand orange with drop shadow.
  - When "Custom" is selected: A native HTML5 date picker (<input type="date">) appears allowing single-day filtering.
- Kitchen Status Selector:
  - Options: All Stages, Received, Preparing, Ready for Pickup, Completed, Cancelled.
- Payment Status Selector:
  - Options: All Payments, Paid, Partially Refunded, Fully Refunded, Pending, Failed.
- Results Counter & Reset Button:
  - Text: "Showing X of Y".
  - Reset Button: Appears only when filters are active. Clicking it clears search text and resets all dropdowns to 'all'.

D. ORDERS TABLE COLUMNS:
1. "Order #" Column:
   - Displays canonical Order Number (e.g., ORD-20261116-0001) in bold monospace font.
   - If the order was created most recently, a green "LATEST" badge is displayed.
   - Displays truncated internal UUID below the order number.
2. "Token" Column:
   - Displays prominent pickup token inside a dark navy pill with brand orange monospace text (e.g., "#101").
3. "Placed At" Column:
   - Clock icon with formatted date and time in Asia/Kolkata timezone (e.g., "16 Nov, 01:15 PM").
4. "Items Summary" Column:
   - Displays itemized snapshot: bold orange quantity (e.g., "2x") + Item Name.
   - If customer mobile was recorded, displays "Tel: 98765XXXXX" in small font-mono.
5. "Payment" Column:
   - Pill badge indicating tender method (Banknote for Cash, CreditCard for UPI) and payment state:
     - PAID (Emerald badge).
     - PENDING (Amber badge).
     - PARTIAL REFUND / REFUNDED (Amber-orange badge).
     - FAILED (Rose-red badge).
6. "Grand Total" Column:
   - Bold, right-aligned currency amount (e.g., "₹320.00").
   - If discount was applied, displays "-₹XX.00 off" in emerald text below.
7. "Kitchen Stage" Column:
   - Centered Badge:
     - 'completed' (Green success badge).
     - 'cancelled' (Red danger badge).
     - 'received' / 'preparing' / 'ready' (Amber warning badge).
8. "Actions" Column:
   - "Details" Button (Eye icon): Opens the slide-over details drawer.
   - "Thermal Receipt" Button (Printer icon): Appears if the order is paid. Opens the printable thermal receipt modal.
   - "Pay" Button (CreditCard icon): Appears if the order is unpaid and not cancelled. Opens the payment collection modal.

E. SLIDE-OVER ORDER DETAILS DRAWER (OrderDetailsDrawer.jsx):
- Header: Order number, pickup token, and close (X) button.
- Metadata Grid: Placed date/time, customer mobile, special cooking notes.
- Line Items Table: Complete item breakdown with unit prices, quantities, and totals.
- Financial Summary Box: Subtotal, Discount Applied, Net Grand Total, Total Paid, and Remaining Balance Due.
- Payment History Log: Audit trail of all transactions and payments recorded for this order.
- Action Buttons in Drawer:
  - "Print Receipt" (if paid).
  - "Collect Payment" (if unpaid).
  - "Cancel Order" (Red button): Opens cancellation confirmation modal.
  - "Process Refund" (Amber button): Appears if the order has been paid. Opens refund modal.

F. ACTION CONFIRMATION MODAL (OrderActionConfirmModal.jsx):
- Dedicated safety dialog for sensitive financial/operational modifications:
  - For Cancel: Displays warning that cancelling marks the order as cancelled on KDS. Requires a mandatory Cancellation Reason (e.g., "Customer walked away", "Item unavailable").
  - For Refund: Allows entering Refund Amount (cannot exceed total paid) and mandatory Refund Reason (e.g., "Wrong item delivered", "Customer complaint").


5. AVAILABLE ACTIONS
--------------------------------------------------------------------------------
1. Search & Filter: Combine text search, date range, and status dropdowns to isolate records.
2. Inspect Order: Click "Details" on any row to open the full drawer.
3. Collect Outstanding Payment: Click "Pay" to record payment for an unpaid order.
4. Reprint Receipt: Click the printer icon to open and print a 58mm/80mm thermal receipt.
5. Cancel Unserved Order: Open details drawer, click "Cancel Order", enter reason, and confirm.
6. Process Customer Refund: Open details drawer, click "Process Refund", enter amount and reason, and confirm.

6. STEP-BY-STEP USAGE GUIDE
--------------------------------------------------------------------------------
SCENARIO A: LOOKING UP A CUSTOMER'S TICKET BY PICKUP TOKEN
1. A customer walks up to the counter holding Token #104 asking about their food.
2. In the Search Input at the top of the table, type: "104".
3. The table immediately filters to show only Token #104.
4. Check the "Kitchen Stage" column: If it says "Ready for Pickup", tell the customer their food is ready on the tray. If "Preparing", inform them it is currently on the grill.

SCENARIO B: COLLECTING PAYMENT FOR A PREVIOUSLY UNPAID ORDER
1. In the Payment status filter dropdown, select "Pending".
2. Locate the order (e.g., ORD-20261116-0003). Notice the yellow "PENDING" badge.
3. Click the green "Pay" button in the Actions column.
4. The POSPaymentModal opens. Collect ₹250 cash or scan the customer's UPI QR code.
5. Click "Confirm Payment".
6. The modal closes, payment status updates to "PAID", paid revenue KPI increments, and the thermal receipt modal opens automatically for printing.

SCENARIO C: CANCELLING AN ACCIDENTAL ORDER
1. Click "Details" on the target order row.
2. In the slide-over drawer, scroll to the bottom and click "Cancel Order".
3. The Confirmation Modal opens.
4. Select or type the reason: "Customer changed mind before preparation started".
5. Click "Confirm Cancellation".
6. Order status updates to "cancelled". The ticket is instantly removed from the active kitchen KDS columns.


7. SYSTEM BEHAVIOUR
--------------------------------------------------------------------------------
- Real-Time Event Sync:
  OrderManagementPage listens for four events:
  - window.addEventListener('fooddesk:order-created', ...)
  - window.addEventListener('fooddesk:order-status-updated', ...)
  - window.addEventListener('fooddesk:payment-completed', ...)
  - window.addEventListener('storage', ...)
  Whenever a cashier places an order at POS or a chef advances a ticket on KDS, the orders table updates automatically without user intervention.
- Refund Calculation & Financial Audit:
  When a refund is recorded via stallDataService.processRefund():
  1. Creates an immutable refund record in the payments ledger.
  2. Updates order.paymentStatus to 'partially_refunded' or 'refunded'.
  3. Increments order.totalRefundedAmount.
  4. Automatically deducts the refunded amount from the stall's net realized revenue in Financial Analytics.

10. RESTRICTIONS AND IMPORTANT NOTES
--------------------------------------------------------------------------------
- Cross-Stall Isolation:
  Stall 1 staff can only view Stall 1 orders. If staff switch to Beverages Stall (stall-2), the order table re-queries immediately and displays only Beverages orders.
- Historical Immutability:
  Cancelling or refunding an order does NOT delete the order record from the database. It preserves the record with updated status flags so that cashiers cannot "hide" missing cash by deleting orders.
- Super Admin Oversight:
  Super Admins attempting to visit /orders see an administrative compliance notice explaining that order processing is reserved for stall counter operators.


11. FREQUENTLY ASKED QUESTIONS (FAQ)
--------------------------------------------------------------------------------
Q1: Can I delete an order completely from the system?
A1: No. In commercial POS systems, completely deleting order tickets is prohibited to prevent internal theft and cash skimming. FoodDesk uses non-destructive cancellations and refunds, preserving an immutable audit trail.

Q2: Can I reprint a receipt from yesterday?
A2: Yes. Select "Yesterday" (or "All Dates") in the date filter presets, locate the order, and click the printer icon. The full thermal receipt will open for printing.

Q3: What does the "LATEST" badge mean?
A3: The green "LATEST" badge appears on the topmost order row to help counter staff immediately identify the order that was just created a few seconds ago.

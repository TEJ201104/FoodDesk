1. FEATURE OVERVIEW
--------------------------------------------------------------------------------
The Central Support Ticket Management Console (/admin/tickets) is the centralized issue resolution, customer dispute, and technical help desk workstation for the platform Super Administrator.

When stall owners or cashiers encounter technical defects, POS errors, payment discrepancies, hardware printer clipping, or operational questions, they submit tickets from their stall support page (/support). All incoming tickets across all stalls converge in this central administrator inbox.

The console provides full lifecycle support governance:
- Centralized Ticket Registry: Aggregates tickets across all stalls with multi-stall filtering.
- Comprehensive Multi-Filter Engine: Filter by Stall (All Stalls, Fast Food, Beverages, Desserts), Category, Priority (Low, Medium, High, Critical), and Status (Submitted, Under Review, In Progress, Resolved, Reopened).
- Interactive Admin Conversation Drawer: Inspect threaded dialogue history, read customer descriptions, and post official administrative replies.
- Formal Lifecycle State Transitions: Advance tickets through the canonical 5-stage lifecycle:
  Submitted → Under Review → In Progress → Resolved (or Reopened).
- Mandatory Resolution Note Enforcement: To mark an issue as "Resolved", the Super Admin is strictly required to provide a clear, non-empty resolution explanation that is delivered to the stall owner.


2. HOW TO ACCESS
--------------------------------------------------------------------------------
- Direct URL: http://localhost:5173/admin/tickets
- Sidebar Navigation: Click "Issue Management" (the fourth item with the MessageSquareWarning icon) in the Super Admin sidebar.
- Platform Dashboard Shortcut: Click "Support Desk" or "Support Inbox" on the Admin Dashboard (/admin/dashboard).

5. AVAILABLE ACTIONS
--------------------------------------------------------------------------------
1. Triage Incoming Tickets: Filter by priority (Critical/High) to address urgent issues first.
2. Filter by Stall: Isolate all tickets submitted by a specific stall.
3. Post Administrative Reply: Send troubleshooting instructions directly to the stall owner.
4. Transition Ticket Stage: Advance status from Submitted → Under Review → In Progress.
5. Resolve Ticket with Explanation: Close the issue by providing a mandatory resolution note.
6. Re-open Investigation: If an owner reopens a ticket, review the follow-up explanation and resume triage.


6. STEP-BY-STEP USAGE GUIDE
--------------------------------------------------------------------------------
SCENARIO: RESOLVING A THERMAL PRINTER HARDWARE TICKET
1. Open /admin/tickets from the Super Admin sidebar.
2. In the Priority filter, select "High".
3. Locate Ticket #TKT-004: "Thermal printer 58mm text margin cut off on right side" submitted by Fast Food Stall.
4. Click "Manage Ticket".
5. The Resolution Drawer opens. Read the description: Staff explains text is clipped on 58mm paper rolls.
6. ACKNOWLEDGE TICKET:
   - Click the "Under Review" button.
   - Status updates to "Under Review", assuring the owner that support is actively looking into it.
7. DISPATCH INVESTIGATION REPLY:
   - In the reply textarea, type: "We have reproduced the issue. It is caused by default CSS print margins on 58mm roll widths. Applying a stylesheet patch."
   - Click "Send Reply".
   - The reply appears immediately in the chat thread and is delivered to the stall owner's screen.
8. APPLY RESOLUTION:
   - Click the green "Resolved" button.
   - The Mandatory Resolution Note box appears.
   - In the resolution field, type: "Patched thermal receipt printable CSS to set width to 48mm with auto-wrap padding. Please test a test print; margins now print cleanly."
   - Click "Confirm & Mark as Resolved".
9. RESULT: The ticket updates to "Resolved" (Emerald badge). In the stall owner's portal, the resolution explanation appears in a prominent green confirmation banner!


7. SYSTEM BEHAVIOUR
--------------------------------------------------------------------------------
- Reply Dispatch (adminService.addTicketReply):
  1. Validates that replyText is non-empty.
  2. Constructs new message object: { id, text, authorName, authorRole: 'super_admin', timestamp }.
  3. Appends message to ticket.messages array.
  4. Dispatches window 'storage' and custom events for multi-tab reactivity.
- Resolution Note Enforcement (adminService.updateTicketStatus):
  1. If nextStatus === 'Resolved': Verifies that resolutionNote is non-empty. If empty, throws an explicit error: "A detailed resolution note is strictly required to resolve a support ticket."
  2. Sets ticket.status = 'Resolved'.
  3. Sets ticket.resolvedAt = new Date().toISOString().
  4. Sets ticket.resolutionNote = resolutionNote.
  5. Appends resolution note as a highlighted message in the conversation thread.
  6. Appends an entry to ticket.history log and the platform activity feed.

--------------------------------------------------------------------------------

  A Super Admin CANNOT close a ticket without typing an explanation. This enforces professional accountability and ensures stall operators always understand how their issue was addressed.


11. FREQUENTLY ASKED QUESTIONS (FAQ)
--------------------------------------------------------------------------------
Q1: What happens if a stall owner is not satisfied with a resolution?
A1: The stall owner can click "Reopen Issue" on their support page, providing a mandatory follow-up comment. The ticket status immediately changes to "Reopened" (Red badge) and reappears at the top of the admin queue.

Q2: Can a Super Admin assign tickets to specific support agents?
A2: In the current release candidate, tickets are managed centrally by the platform administrator team. In enterprise multi-agent releases, individual support agent assignment is supported.

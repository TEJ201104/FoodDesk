1. FEATURE OVERVIEW
--------------------------------------------------------------------------------
This document covers the secondary and foundational governance tools available exclusively to the platform Super Administrator:
1. The Owner Management Registry (/admin/owners): A centralized administrative directory of all registered stall owners, contact credentials, multi-stall authorization mappings, and tenant isolation status.
2. The Platform Settings & Governance Hub (/admin/settings): System diagnostic parameter inspection (Web Locks API concurrency, Asia/Kolkata timezone anchor, local-first storage health), and the high-risk Factory Demo Data Reset workflow protected by a typed safety confirmation phrase.


2. HOW TO ACCESS
--------------------------------------------------------------------------------
- Owner Management: http://localhost:5173/admin/owners (or click "Owner Management" in the admin sidebar).
- Platform Settings: http://localhost:5173/admin/settings (or click "Platform Settings" in the admin sidebar).


3. SCREEN LAYOUT
--------------------------------------------------------------------------------
A. OWNER MANAGEMENT SCREEN (/admin/owners):
- Header: Title ("Stall Owner Management"), subtitle, and refresh button.
- Multi-Tenant Security Audit Card: Elevated navy banner confirming tenant mapping (Owner 1 authorized for stall-1 & stall-2; Owner 2 locked strictly to stall-3).
- Filter Toolbar: Keyword search box, Filter by Assigned Stall dropdown, and "Multi-Stall Owners Only" checkbox.
- Owners Table: Directory displaying Owner Avatar & Name, Contact Email & Phone, Authorized Stalls pills, Multi-Stall status badge, and "Inspect Owner" action button.
- Owner Details Drawer (Conditional): Slide-out drawer displaying comprehensive owner profile and assigned stall summaries.

B. PLATFORM SETTINGS SCREEN (/admin/settings):
- Header: Title ("Platform Settings & Governance"), subtitle, and Super Admin badge.
- Success Banner (Conditional): Appears after executing demo data reset confirming factory restoration.
- Two-Column Diagnostic & Reset Grid:
  - Left Card: "System Diagnostics & Architecture" (environment, storage keys, Web Locks API status, timezone anchor, stall/user baselines).
  - Right Card: "High-Risk Environment Operations & Demo Data Reset" (warning banner, explanation, and "Reset All Demo Data" button).
- Reset Confirmation Modal (Conditional): Red danger dialog requiring the operator to type "RESET DEMO DATA" exactly to confirm.

6. STEP-BY-STEP USAGE GUIDE
--------------------------------------------------------------------------------
SCENARIO A: VERIFYING MULTI-STALL AUTHORIZATION MAPPINGS
1. Log in as Super Admin and open /admin/owners.
2. In the table, locate "Owner 1".
3. Check the "Authorized Stalls" column: Notice two pills: "stall-1" and "stall-2".
4. Check the "Account Type" column: Notice the orange "Multi-Stall (2)" badge.
5. Locate "Owner 2".
6. Check "Authorized Stalls": Notice exactly one pill: "stall-3".
7. Check "Account Type": Notice the gray "Single-Stall (1)" badge.
8. Click "Inspect Owner" on Owner 2 to verify contact details and confirm that Owner 2 has zero access to stall-1 or stall-2.

SCENARIO B: EXECUTING A FACTORY DEMO DATA RESET
1. Open /admin/settings from the Super Admin sidebar.
2. In the right-hand card, click the red "Reset All Demo Data to Factory Baseline" button.
3. The Reset Confirmation Modal opens displaying a critical warning.
4. In the confirmation input field, type: "RESET DEMO DATA" (must be uppercase).
5. Notice that the red "Confirm & Execute Reset" button becomes enabled.
6. Click "Confirm & Execute Reset".
7. An animated spinner displays for 600ms, followed by a green success banner:
   "Factory Demo Data Restored Successfully. All 3 stalls, 30 menu items, initial orders, payments, expenses, inventory baselines, and support tickets have been reset to their pristine factory seed state. Your Super Admin session remains active."
8. All modified orders, expenses, and test data are now reset to pristine factory baselines!


7. SYSTEM BEHAVIOUR
--------------------------------------------------------------------------------
- Demo Data Reset Routine (adminService.resetPlatformDemoData):
  1. Preserves the active Super Admin session object from localStorage.
  2. Overwrites 'fooddesk_stalls' with initialStalls.
  3. Overwrites 'fooddesk_menu' with initialMenu.
  4. Overwrites 'fooddesk_orders' with initialOrders.
  5. Overwrites 'fooddesk_payments' with initialPayments.
  6. Overwrites 'fooddesk_expenses' with initialExpenses.
  7. Overwrites 'fooddesk_inventory' with initialInventory.
  8. Overwrites 'fooddesk_tickets' with initialTickets.
  9. Restores the preserved admin session back to 'fooddesk_session'.
  10. Dispatches window 'storage' event to notify all open tabs.
- Concurrency via Web Locks API:
  In modern browsers supporting navigator.locks, critical operations acquire an exclusive lock ('fooddesk_data_lock') before writing to storage, preventing race conditions.

10. RESTRICTIONS AND IMPORTANT NOTES
--------------------------------------------------------------------------------
- High-Risk Destructive Action:
  Resetting demo data completely wipes any newly created orders, test expenses, custom menu items, and wastage logs created during demonstration sessions. It should only be used when preparing for a fresh demonstration.
- Session Preservation:
  The reset routine is specially engineered to preserve the Super Admin's active session, preventing unexpected logout mid-presentation.


11. FREQUENTLY ASKED QUESTIONS (FAQ)
--------------------------------------------------------------------------------
Q1: Can a stall owner access Platform Settings to reset demo data?
A1: Absolutely not. Platform Settings (/admin/settings) is strictly protected by RoleGuard. Stall owners who attempt to navigate to this URL are automatically bounced back to /dashboard.

Q2: Can I assign an existing stall to a different owner?
A2: In the demonstration build, owner mappings are defined in the verified seed baseline (Owner 1 mapped to stall-1 & stall-2; Owner 2 mapped to stall-3). In production releases, an owner re-assignment modal allows transferring stall ownership.

Q3: What happens to open browser tabs when demo data is reset?
A3: The storage event triggers across all open tabs, causing them to rehydrate their state from the restored factory baseline.

1. FEATURE OVERVIEW
--------------------------------------------------------------------------------
The Public Order Tracking Portal (/track/:stallSlug/:orderNumber) is an unauthenticated, real-time order status web tracking application for customers.

In busy food courts and commercial markets, customers who have placed an order at the counter typically crowd around the pickup window, repeatedly asking staff: "Is Token 104 ready yet?" or "How much longer for my burger?". This creates intense noise, blocks incoming customers, and distracts kitchen cooks.

FoodDesk solves this by providing a live, mobile-friendly order progress tracker. A tracking URL or QR code is printed directly onto the customer's thermal receipt slip (e.g., http://localhost:5173/track/fast-food-stall/ORD-20261116-0001). Customers scan the receipt with their smartphone or enter their order number on the tracking page to view a beautiful, live animated milestone progress bar that synchronizes in real time with the kitchen's Kitchen Display System (KDS).

Key capabilities include:
- Double-Key URL Validation: Strict security binding requiring both a valid stall slug AND an authorized order number, enforcing complete multi-stall isolation.
- Five Canonical Order Milestones:
  1. Order Received (Ticket recorded at counter).
  2. Preparing (Food is actively cooking in the kitchen).
  3. Ready for Pickup (Food is boxed/plated and waiting on the counter).
  4. Completed & Served (Order handed over to customer).
  5. Cancelled (Special milestone displayed if the order was voided).
- Prominent Pickup Token Callout: Displays the customer's 3-digit token (e.g., Token #104) in giant, high-contrast font.
- Masked PII Protection: Protects customer privacy by masking telephone numbers (e.g., +91 ••••• •1234).
- Real-Time Reactive Updates: Automatically advances to "Ready for Pickup" the exact millisecond the chef taps "Mark as Ready" on the KDS, without requiring the customer to refresh their browser.


2. HOW TO ACCESS
--------------------------------------------------------------------------------
- Direct Public URLs:
  - Base Tracker: http://localhost:5173/track/:stallSlug
  - Direct Order Tracker: http://localhost:5173/track/:stallSlug/:orderNumber
  - Example: http://localhost:5173/track/fast-food-stall/ORD-20261112-0001
- Receipt QR Code: Printed on the bottom of the customer's thermal receipt slip.
- Application Shortcuts:
  - Login Page Footer: Click "Customer Order Tracker".
  - Stall Owner Sidebar: Click "Order Tracker" under Customer Portals.
- Zero Authentication: Requires NO login or password. Completely accessible to the guest.

7. SYSTEM BEHAVIOUR
--------------------------------------------------------------------------------
- Double-Key Isolation Security:
  stallDataService.getPublicOrderTracking(stallSlug, orderNumber) requires:
  1. stall.slug === stallSlug.
  2. order.orderNumber === orderNumber.
  3. order.stallId === stall.id.
  If a customer attempts to query a Fast Food order number against the Beverages stall slug (e.g., /track/beverages-stall/ORD-FASTFOOD-0001), the service strictly rejects the lookup: "Order [Number] does not belong to stall [Slug]."
- Real-Time Event Subscription:
  The tracking page subscribes to:
  - window.addEventListener('fooddesk:order-status-updated', ...)
  - window.addEventListener('storage', ...)
  When the KDS updates order.orderStatus, the tracking view recomputes its milestone step within 5 milliseconds.

10. RESTRICTIONS AND IMPORTANT NOTES
--------------------------------------------------------------------------------
- Case-Insensitive Order Number Lookup:
  The search input automatically normalizes entered order numbers to uppercase (e.g., ord-20261116-0001 becomes ORD-20261116-0001).
- Cross-Stall Double-Key Enforcement:
  Orders from Stall 1 can never be tracked under Stall 2 or Stall 3 URLs, preventing cross-tenant information leakage.


11. FREQUENTLY ASKED QUESTIONS (FAQ)
--------------------------------------------------------------------------------
Q1: Does a customer have to install an app to track their order?
A1: No! It runs entirely in the phone's native web browser (Safari, Chrome, Firefox, etc.) without requiring an app store download.

Q2: What happens if an order is cancelled?
A2: If an order is cancelled at the counter, the tracking screen immediately updates to display a red "Order Cancelled" notification advising the customer to speak with the cashier.

Q3: Does the customer have to keep refreshing the webpage?
A3: No! The page uses reactive event listeners. As soon as the kitchen updates the status, the progress stepper updates automatically on the customer's screen.
